# Read-only device employee preview
AT2 administration: Devices > Device Employee List. Select a registered terminal, confirm no enrollment is occurring, send Query Employees, refresh after the next authorized poll. The one-shot command is DATA QUERY USERINFO; it does not enable general commands. Existing token/verified-IP/explicit serial-only authorization applies. Serial-only is not true authentication, and names can be spoofed.

During the capture window, matching USERINFO or recognizable OPERLOG user batches for that terminal are intercepted before normal raw-log creation and employee import. Only PIN/name are stored in the app's temporary file cache; dispatch/ACK metadata remains in the standard audit ledger. Normal attendance uploads remain on their existing path. Concurrent enrollment/user data in matching replies is also held, because some firmware does not send a query identifier for roster batches. Avoid new enrollment during preview. Do not redeploy or clear cache during capture. End only after verifying all expected batches and at least 90 seconds of quiet. Results expire after 30 minutes and capture guard after two hours; unrecognized formats or late uploads outside capture may use normal ingestion. The feature is designed for the current single dual-host app container, not separate pods without a shared cache. A USERINFO result does not prove fingerprint availability: verify a matching device ACK and test the actual finger on the terminal.

Tests: verify on one terminal, compare original employee/adms employee/registration counts before and after, check command and ACK audit, record names, confirm no roster raw logs, compare terminal count manually, ensure ATTLOG still flows. Never enable global command dispatch to use this feature.
