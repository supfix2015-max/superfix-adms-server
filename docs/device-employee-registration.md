# Device employee registration (draft)
Run docs/sql/adms-device-employee-registration.sql once as DBA in Att2000_V4, before deploying. It creates only an adms review table and a procedure that checks the registered device and inserts a new dbo.Employee badge/name if absent. No existing employee is modified. The writer gets EXECUTE on the procedure only (not direct INSERT/UPDATE/DELETE on dbo.Employee).
Set ZKTECO_EMPLOYEE_REGISTRATION_AUTO=true only after testing source authorization. Source authentication reuses the live fingerprint-review token/verified IP policy and requires fingerprint-review dispatch enabled. Without verified source a new registration is pending for review in AT2 Admin > Employee Registration Requests. HTTP is supported but not encrypted; use private links where possible.
Existing same-name uploads are recorded as existing; different names are flagged as duplicate and held on the relevant source/target fingerprint-review path. A matching name does not prove identity. A duplicate cannot be overwritten, and a new badge must be assigned and enrolled on the terminal by authorized staff. The historical conflicting badge stays blocked for that terminal; there is no conflict-release action in this draft. No changes to attendance ingestion or ZenHR are made; an identity collision at a terminal can still affect its attendance punches and requires immediate HR correction. Ordinary USERINFO from unverified registered sources is held rather than used to overwrite the local employee record. Non-ASCII or over-40-byte employee names are not written automatically; review/correct the terminal name. No prior raw logs are replayed automatically. Fingerprint template approval remains separate.
Test: new authorized registration -> one original row; repeated upload -> same row; duplicate with different name -> original unchanged and warning; unknown source -> review; template conflicts -> no queue or dispatch; regression test ATTLOG and existing USERINFO including mixed packets. Do not enable auto until verified on a test device.
